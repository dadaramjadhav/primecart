# Grafana CrashLoopBackOff Due to Duplicate Default Datasources

## Incident

- **Date:** 2026-07-27
- **Namespace:** `primecart-observe`
- **Workload:** `deployment/monitoring-grafana`
- **Status:** Resolved

## Symptoms

The Grafana pod was not becoming ready:

```text
READY   STATUS
2/3     CrashLoopBackOff
```

The dashboard and datasource sidecars were healthy, but the main `grafana`
container repeatedly exited with code 1. Readiness and liveness probes failed
because nothing was listening on port 3000.

## Root Cause

Grafana received two Prometheus provisioning files with `isDefault: true`:

1. `monitoring-kube-prometheus-grafana-datasource`, generated by the
   `kube-prometheus-stack` Helm chart.
2. `grafana-prometheus-datasource`, defined in
   `k8s/observability/grafana/prometheus-datasource.yaml`.

Grafana permits only one default datasource per organization and terminated
during provisioning with:

```text
Datasource provisioning error: datasource.yaml config is invalid.
Only one datasource per organization can be marked as default
```

## Diagnosis

The failure was identified with:

```bash
kubectl get pods -n primecart-observe \
  -l app.kubernetes.io/name=grafana

kubectl logs -n primecart-observe \
  deployment/monitoring-grafana \
  -c grafana --previous

kubectl get configmap,secret -n primecart-observe \
  -l grafana_datasource=1 -o yaml
```

The PVC was bound, the image was available, and both sidecars were running,
which ruled out storage, image-pull, and sidecar failures.

## Resolution

The custom Prometheus datasource was changed to non-default because the Helm
chart already provisions Prometheus as the default:

```yaml
isDefault: false
```

The corrected ConfigMap was applied and Grafana was restarted:

```bash
kubectl apply -f k8s/observability/grafana/prometheus-datasource.yaml
kubectl rollout restart deployment/monitoring-grafana \
  -n primecart-observe
kubectl rollout status deployment/monitoring-grafana \
  -n primecart-observe --timeout=5m
```

## Verification

After the rollout:

```text
READY   STATUS    RESTARTS
3/3     Running   0
```

Grafana logged `All modules healthy`, listened on port 3000, and was available
through:

```text
http://grafana.primecart.localhost
```

## Prevention

- Keep only one datasource marked `isDefault: true` per Grafana organization.
- Check Helm-generated datasource ConfigMaps before adding custom provisioning.
- After datasource changes, inspect all resources labeled
  `grafana_datasource=1` and validate the Grafana rollout.
