# PrimeCart Local HTTPS Setup

This guide describes how to enable trusted local HTTPS for PrimeCart services
exposed through the NGINX Ingress Controller.

## HTTPS architecture

Local TLS terminates at the Ingress:

```text
Browser
  |
  | HTTPS
  v
NGINX Ingress
  |
  | HTTP inside the cluster
  v
Kubernetes Service
  |
  v
Application Pod
```

Applications do not need to manage TLS certificates directly. NGINX presents
the certificate to clients and forwards requests to the existing HTTP
Services.

## Local domains

PrimeCart uses these local domains:

```text
primecart.localhost
api.primecart.localhost
auth.primecart.localhost
grafana.primecart.localhost
prometheus.primecart.localhost
product.primecart.localhost
payment.primecart.localhost
cart.primecart.localhost
customer.primecart.localhost
inventory.primecart.localhost
order.primecart.localhost
sbadmin.primecart.localhost
```

A wildcard certificate for `*.primecart.localhost` covers the subdomains, but
not the root `primecart.localhost` domain. Both names must be included.

## Install mkcert

Install `mkcert` on macOS:

```bash
brew install mkcert
mkcert -install
```

The second command installs a local certificate authority into the system
trust store. Certificates generated by this installation will be trusted only
on machines where its local CA is installed.

## Generate the certificate

Create a local directory for certificate files:

```bash
mkdir -p .certs
```

Generate a certificate for the root and wildcard domains:

```bash
mkcert \
  -cert-file .certs/primecart.crt \
  -key-file .certs/primecart.key \
  "primecart.localhost" \
  "*.primecart.localhost"
```

Add the directory to `.gitignore`:

```gitignore
.certs/
```

Never commit the private key.

## Create TLS secrets

Ingress TLS secrets are namespace-scoped. The current ingress resources expose
services from `primecart-app`, `primecart-infra`, and `primecart-observe`.
Create the same TLS secret in each namespace:

```bash
kubectl create secret tls primecart-local-tls \
  --cert=.certs/primecart.crt \
  --key=.certs/primecart.key \
  --namespace=primecart-app
```

```bash
kubectl create secret tls primecart-local-tls \
  --cert=.certs/primecart.crt \
  --key=.certs/primecart.key \
  --namespace=primecart-infra
```

```bash
kubectl create secret tls primecart-local-tls \
  --cert=.certs/primecart.crt \
  --key=.certs/primecart.key \
  --namespace=primecart-observe
```

Verify the secrets:

```bash
kubectl get secret primecart-local-tls \
  --namespace=primecart-app

kubectl get secret primecart-local-tls \
  --namespace=primecart-infra

kubectl get secret primecart-local-tls \
  --namespace=primecart-observe
```

For repeatable deployments, manage these secrets through an approved secret
management process instead of committing certificate data to Git.

## Configure HTTPS Ingress

Update each Ingress in
`k8s/networking/ingress/primecart-local-ingress.yaml`.

Add redirect annotations:

```yaml
metadata:
  annotations:
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
    nginx.ingress.kubernetes.io/force-ssl-redirect: "true"
```

Add the TLS host and secret:

```yaml
spec:
  ingressClassName: nginx
  tls:
    - hosts:
        - api.primecart.localhost
      secretName: primecart-local-tls
  rules:
    - host: api.primecart.localhost
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: api-gateway
                port:
                  number: 8181
```

Each Ingress must reference the TLS secret in its own namespace. Repeat the
`tls.hosts` entry using that Ingress's hostname.

## Configure Keycloak

Keycloak must publish an HTTPS issuer while continuing to accept HTTP from the
Ingress inside the cluster:

```yaml
env:
  - name: KC_HOSTNAME
    value: https://auth.primecart.localhost

  - name: KC_PROXY_HEADERS
    value: xforwarded

  - name: KC_HTTP_ENABLED
    value: "true"
```

The external issuer becomes:

```text
https://auth.primecart.localhost/realms/primecart
```

Apply the Keycloak manifest and restart its Deployment:

```bash
kubectl rollout restart deployment/keycloak \
  --namespace=primecart-infra

kubectl rollout status deployment/keycloak \
  --namespace=primecart-infra \
  --timeout=10m
```

## Configure Spring Boot resource servers

Set the issuer URL used by each secured application:

```yaml
- name: SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_ISSUER_URI
  value: https://auth.primecart.localhost/realms/primecart
```

The JWK endpoint may remain on the internal Kubernetes network:

```yaml
- name: SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_JWK_SET_URI
  value: http://keycloak.primecart-infra:8080/realms/primecart/protocol/openid-connect/certs
```

This configuration validates the external HTTPS issuer while retrieving
signing keys over the cluster network.

The configured issuer must exactly match the `iss` claim in Keycloak access
tokens.

## Configure Keycloak clients

Update the UI client's Keycloak settings:

```text
Root URL:            https://primecart.localhost
Valid redirect URIs: https://primecart.localhost/*
Web origins:         https://primecart.localhost
```

Only retain HTTP redirect URLs when HTTP access is intentionally supported.

## Configure the UI

Configure the UI to use HTTPS endpoints:

```text
API URL:      https://api.primecart.localhost
Keycloak URL: https://auth.primecart.localhost
```

If these values are embedded at build time, rebuild and redeploy the UI image.
For reusable images across environments, prefer a runtime configuration file
or environment substitution performed when the container starts.

Do not load HTTP APIs or assets from the HTTPS UI. Browsers block this as mixed
content.

## Apply the local overlay

Render the overlay before applying it:

```bash
kubectl kustomize k8s/overlays/local
```

Apply it:

```bash
kubectl apply --kustomize k8s/overlays/local
```

Restart application Deployments after issuer or UI configuration changes:

```bash
kubectl rollout restart deployment \
  --namespace=primecart-app
```

## Verification

Check Ingress resources:

```bash
kubectl get ingress --all-namespaces
```

Verify HTTPS and HTTP redirection:

```bash
curl --head http://primecart.localhost
curl --head https://primecart.localhost
curl --head https://api.primecart.localhost
```

The HTTP request should redirect to HTTPS, and HTTPS requests should complete
without certificate warnings.

Verify Keycloak discovery:

```bash
curl \
  https://auth.primecart.localhost/realms/primecart/.well-known/openid-configuration
```

Confirm that the response contains:

```json
{
  "issuer": "https://auth.primecart.localhost/realms/primecart"
}
```

Finally:

1. Open `https://primecart.localhost`.
2. Sign in through Keycloak.
3. Confirm the browser shows no certificate or mixed-content errors.
4. Call an authenticated API.
5. Confirm the access token `iss` claim uses the HTTPS Keycloak URL.

## Production differences

`mkcert` is appropriate only for local development. Production should use:

- A publicly trusted certificate authority
- `cert-manager` or a cloud certificate service
- Real DNS domains
- Automated certificate renewal
- Environment-specific Keycloak issuers and redirect URLs
- TLS policies appropriate for the production ingress controller
